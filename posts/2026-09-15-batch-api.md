> **한 줄 요약:** 벤더들의 배치 API는 **"지금 당장 답이 필요 없는 요청"**을 모아 보내면 **대폭 할인(대개 50%)**해주는 창구입니다. 문서 분류·요약·태깅·평가처럼 결과를 몇 시간 뒤 받아도 되는 작업이 대상 — 스팟 인스턴스가 컴퓨팅에 한 일을 LLM 호출에 하는 셈이에요.

## 실시간 API의 숨은 낭비

RAG 인덱싱용 문서 요약 1만 건, 고객 문의 월간 분류, 골든셋 평가 500문항 — 전부 **결과를 사람이 앉아서 기다리지 않는 작업**입니다. 그런데 실시간 API(요청 즉시 응답)로 부르면 벤더는 "즉시 응답"을 위한 용량을 예약해두고 그 값을 받습니다. 스팟 글의 논리 그대로 — **즉시성을 안 사면 싸집니다.**

## 배치 API의 모양

```
1. 요청 파일 만들기 — 한 줄에 요청 하나 (JSONL)
2. 업로드 → 배치 작업 생성
3. 기다림 (수십 분 ~ 최대 24시간, 벤더별 상이)
4. 결과 파일 다운로드 → 요청 ID로 짝 맞추기
```

```jsonl
{"custom_id":"doc-0001","params":{"model":"...","max_tokens":300,"messages":[{"role":"user","content":"다음 문서를 3줄로 요약: ..."}]}}
{"custom_id":"doc-0002","params":{...}}
```

`custom_id`가 핵심입니다 — 결과는 **순서 보장이 없으니** 이걸로 원본과 매칭합니다. 그리고 결과 파일엔 성공한 것과 실패한 것(형식 오류, 콘텐츠 정책, 일시 오류)이 섞여 오니, 실패분만 골라 재제출하는 로직이 필요해요.

## 어울리는 일 / 안 어울리는 일

**어울림 (지연 허용):**
- RAG 인덱싱 — 청크 요약·키워드·메타데이터 추출(메타데이터 필터링 글의 그 LLM 추출)
- 대량 분류·태깅 — 문의 유형, 감성, 라우팅 라벨
- 골든셋 평가 실행 — 평가 글의 그 루프를 야간에 반값으로
- 합성 데이터·LoRA 학습용 예시 생성
- 주간 리포트류 정기 요약

**안 어울림:**
- 사용자 대면 응답 (당연히)
- 에이전트 루프 — 도구 호출 결과를 보고 다음 요청을 정하는 구조는 배치로 못 쪼갭니다
- 완료 시각이 계약된 SLA 작업 — 24시간 창은 "최대"이고 보장이 아니니

## 설계 요령

**① 실시간 경로와 배치 경로를 처음부터 나누기.** LLM 게이트웨이 글의 그 관문에서 요청 유형별로 라우팅 — "지연 허용" 플래그가 붙은 요청은 배치 큐로. 한 서비스 안에 두 경로가 공존하는 게 정상입니다.

**② 프롬프트 캐싱과의 관계.** 배치는 이미 할인이지만, 요청들이 **같은 시스템 프롬프트를 공유**하면 캐싱 할인도 중첩되는 경우가 있습니다(벤더별 정책 확인). 어느 쪽이든 프롬프트 캐싱 글의 규칙(고정부 앞으로)은 배치 파일에서도 그대로 지키세요.

**③ 멱등성.** 배치가 중간에 실패하거나 결과를 두 번 처리하면 같은 문서가 두 번 인덱싱됩니다. `custom_id`를 처리 완료 표로 관리하고, 결과 반영은 upsert로 — 임베딩 캐시 글의 해시 키 방식이 여기서도 중복을 막아줍니다.

**④ 크기 조절.** 배치 하나에 너무 많이 넣으면 실패 시 재제출 단위가 커집니다. 수천 건 단위로 쪼개고, 배치별 상태(제출/완료/실패 건수)를 기록하는 표가 운영의 눈이에요.

**⑤ 비용 대시보드에 별도 항목으로.** 배치 지출과 실시간 지출을 나눠 보면 "실시간으로 부르고 있던 배치성 작업"이 드러납니다 — 그게 다음 절감 후보.

## 자체 서빙이라면

로컬 LLM 글의 그 GPU 서버라면 배치 API 대신 **오프피크 스케줄링**이 같은 역할입니다 — 낮에는 실시간 서빙, 야간에는 vLLM의 오프라인 배치 모드로 대량 처리. GPU 가동률을 채우는 것이 로컬의 손익을 결정한다고 했으니, 배치성 작업을 야간에 몰아넣는 게 그 가동률을 만드는 가장 쉬운 방법이기도 하죠.

## 한 줄 정리

**결과를 기다리지 않는 작업은 배치로.** JSONL + custom_id + 실패분 재제출 + 멱등 반영이 뼈대고, 게이트웨이에서 실시간/배치 경로를 나누세요. 인덱싱·분류·평가·합성이 단골이고 — 같은 일을 반값에 하는 가장 단순한 방법입니다.
