> **한 줄 요약:** scp는 **복사기**(매번 전체를 다시), rsync는 **교정 담당**(양쪽을 비교해 **바뀐 부분만** 전송)입니다. 재실행하면 이어서 하고, 매일 돌리면 증분 백업이 되죠. 단 하나의 유명한 함정 — **원본 경로 끝의 슬래시 유무**가 결과를 바꿉니다.

## scp의 한계는 구조적이다

10GB 디렉토리를 scp로 보내다 98%에서 끊기면 — **처음부터**입니다. 어제 보낸 디렉토리에서 파일 3개가 바뀌어 다시 보내면 — **10GB 전부** 다시 갑니다. scp는 "복사해서 붙여넣기"라서 상대편에 뭐가 있는지 안 봐요.

rsync의 발상: **보내기 전에 양쪽을 비교하자.** 파일 목록·크기·수정시각(필요시 체크섬)을 대조해 **다르거나 없는 것만** 전송합니다. 큰 파일 하나 안에서도 바뀐 블록만 보내는 델타 알고리즘이 이름의 유래고요. 그래서 —

- 어제 10GB 보냈고 오늘 30MB 바뀌었으면 → **오늘은 30MB만**
- 끊겨도 재실행하면 → 이미 간 파일은 건너뛰고 **이어서**
- 매일 cron으로 돌리면 → 그 자체가 증분 백업 파이프라인

## 기본형과 옵션 다섯 개

```bash
rsync -avz --progress /data/ user@server:/backup/data/
```

- **-a** (archive): 권한·시각·심볼릭링크·재귀를 통째로 보존 — 사실상 항상 켭니다. 수정시각 보존은 다음 실행의 비교 기준이 되므로 증분의 전제이기도 해요.
- **-v / --progress**: 뭘 보내는지, 얼마나 남았는지.
- **-z**: 전송 압축 — 텍스트·로그엔 효자, 이미 압축된 것(영상, gz)엔 CPU 낭비.
- **--partial** (또는 -P = --partial --progress): 끊긴 **대용량 파일 하나**도 조각을 보존해 이어받기. 불안한 회선의 필수품.
- **-n** (--dry-run): **실행 없이 뭘 할지 미리보기.** 특히 --delete와 함께라면 의무입니다 — 아래에서.

전송은 SSH 위로 가니(배스천의 ProxyJump도 그대로: `rsync -e "ssh -J bastion" ...`) 방화벽·키 체계는 scp와 동일합니다.

## 그 유명한 함정: 끝 슬래시

rsync 사고의 8할입니다.

```bash
rsync -av /data  server:/backup/    # → /backup/data/...   (디렉토리째)
rsync -av /data/ server:/backup/    # → /backup/...        (알맹이만)
```

**원본 끝에 슬래시가 있으면 "안의 내용물을", 없으면 "그 디렉토리 자체를"** 보냅니다. 한 글자 차이로 한 단계 중첩되거나 풀리죠. 외우는 요령: **슬래시 = 뚜껑 열고 붓기.** 헷갈리면 -n으로 목적지 경로를 먼저 확인 — 이게 dry-run이 존재하는 이유입니다.

## --delete: 미러링의 칼

기본 rsync는 원본에서 지워진 파일을 목적지에서 안 지웁니다(쌓이기만). 완전한 미러가 필요하면:

```bash
rsync -avn --delete /data/ server:/backup/data/   # 반드시 -n 먼저!
# "deleting old-report.pdf" 목록을 눈으로 확인한 뒤
rsync -av --delete /data/ server:/backup/data/
```

--delete + 슬래시 실수 + 오타 경로가 만나면 **목적지를 통째로 비우는** 대참사가 됩니다. 그래서 규칙: **--delete는 dry-run 없이 절대 실행하지 않는다.** 그리고 미러는 백업이 아니라는 것도 — 원본의 랜섬웨어·실수 삭제가 그대로 미러에 복제되니, 시점 보존(스냅샷 글의 그것)과는 역할이 다릅니다.

## 실전 레시피

```bash
# 매일 새벽 증분 백업 (cron — 그 글의 PATH·로그 원칙대로)
rsync -az --delete --exclude='*.tmp' --exclude='cache/' \
      /srv/app/ backup@10.0.5.20:/backup/app/ >> /var/log/rsync-app.log 2>&1

# 대용량 이관: 서비스 중 1차 동기화 → 정지 → 차액만 2차 → 전환
rsync -avz --progress /var/lib/data/ new-server:/var/lib/data/   # 몇 시간 걸려도 OK (서비스 중)
# 점검시간에 서비스 정지 후:
rsync -avz --delete /var/lib/data/ new-server:/var/lib/data/     # 차액 몇 분이면 끝
```

두 번째가 관리형 DB 이관 글에서 말한 "복제 후 짧은 전환"의 파일 버전입니다 — **큰 덩어리는 미리, 전환 창에는 차액만.** 다운타임이 시간 단위에서 분 단위로 줄어요.

## 한 줄 정리

rsync = **비교 후 차액만 + 끊긴 곳부터.** -a는 기본, --partial은 대용량, --delete는 dry-run 먼저, 그리고 **끝 슬래시(뚜껑 열기)**만 몸에 새기면 — 복사·백업·이관·미러링이 명령 하나로 통일됩니다.
