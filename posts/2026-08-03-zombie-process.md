> **한 줄 요약:** 좀비(Z, defunct)는 **이미 종료된 프로세스의 잔여 기록**입니다 — 부모가 종료 코드를 회수(wait)해줄 때까지 커널이 보관하는 사망 신고서죠. 그래서 kill이 안 통합니다(죽은 걸 또 죽일 수 없음). **치우는 방법은 부모를 고치거나, 부모를 없애는 것**뿐입니다.

[[diagram:zombie-reap]]

## 발견의 순간

```bash
$ ps aux | grep defunct
worker   23841  0.0  0.0    0     0 ?  Z  10:02  0:00 [python] <defunct>
$ kill -9 23841
$ ps aux | grep defunct
worker   23841  ...  Z  ...  [python] <defunct>     # 그대로다?!
```

kill -9는 만능 아니었나요? — 좀비에게는 아닙니다. 이유를 알면 당연해져요.

## 정체: 사망 신고서를 안 떼 간 것

프로세스가 종료되면 커널은 메모리·fd 등 자원을 즉시 회수합니다. 그런데 딱 하나, **프로세스 테이블의 항목(종료 코드, PID)**은 남겨둡니다. 왜? **부모가 "우리 애 어떻게 죽었어요?"라고 물어볼 권리(wait 시스템콜)**가 있기 때문이에요. 종료 코드는 부모가 떼 가야 하는 사망 신고서고, 그걸 보관 중인 상태가 Z입니다.

그래서 —
- **좀비는 CPU도 메모리도 안 씁니다.** 몇 개쯤은 완전히 무해해요.
- **kill이 안 통합니다.** 시그널은 살아있는 프로세스에게 보내는 것인데, 얘는 이미 죽었으니까요.
- **문제의 주어는 죽은 자식이 아니라 산 부모입니다.** 부모가 wait()를 안 부르고 있는 것 — 자식을 fork해놓고 뒷정리 코드를 빠뜨린 버그죠.

## 그럼 언제 문제가 되나

두 경우입니다.

**① 쌓일 때.** 좀비 하나는 무해하지만, 워커를 계속 fork하면서 한 번도 회수하지 않는 데몬은 좀비를 수천 개 만듭니다. PID는 유한한 자원이라(기본 수만 개), 다 차면 **시스템 전체가 새 프로세스를 못 만듭니다** — fork 실패는 fd 고갈보다 더 광범위한 마비예요.

**② 좀비인 줄 알았는데 아닐 때.** D 상태(디스크 대기, load average 글의 그것)를 좀비로 오인하는 경우가 많습니다. Z는 무해한 기록, D는 I/O에 붙들린 산 프로세스 — 대응이 완전히 다르니 상태 글자부터 확인하세요.

```bash
ps -eo state,pid,ppid,cmd | awk '$1=="Z"'     # 좀비 목록 + 부모 PID
ps -eo state | sort | uniq -c                  # 상태별 분포 한눈에
```

## 치우는 법 — 부모를 향해

**방법 1: 부모에게 회수 신호 (SIGCHLD).**

```bash
kill -CHLD <부모PID>
```

부모가 정상적인 프로그램이라면 "자식 정리하세요" 알림을 받고 wait를 부릅니다. 이걸로 치워지면 부모의 핸들러는 있는데 놓친 케이스.

**방법 2: 부모를 죽인다 — 고아는 init이 거둔다.**

방법 1이 안 통하면(회수 코드 자체가 없음) 부모를 재시작합니다. 부모가 죽으면 좀비들은 **고아가 되어 PID 1(init/systemd)에 입양**되는데, init은 직업이 자식 회수인 존재라 **입양 즉시 좀비가 사라집니다.** port-in-use 글에서 본 고아 입양이 여기선 해결책으로 작동하는 셈이죠.

**방법 3 (근본): 코드를 고친다.**

```python
import signal
# 자식의 종료를 자동 회수 — "우리 집은 사망신고 자동화"
signal.signal(signal.SIGCHLD, signal.SIG_IGN)

# 또는 명시적으로: fork한 만큼 os.waitpid(...) 로 거둬들이기
# subprocess 모듈을 쓴다면 .wait() / .communicate() 호출 누락이 단골 범인
```

셸 스크립트라면 백그라운드 작업(`&`) 뒤의 `wait`가 같은 역할입니다. 그리고 **컨테이너에서 좀비가 쌓인다면** — 컨테이너의 PID 1이 내 앱이라서 입양은 되는데 회수를 안 하는 상황입니다. `docker run --init` (또는 tini)으로 회수 전담 PID 1을 세우는 게 정석이에요.

## 한 줄 정리

좀비는 **부모가 안 떼 간 사망 신고서**라 kill이 무의미합니다. 몇 개면 무시, 쌓이면 PID 고갈 — 치료는 항상 부모 쪽(SIGCHLD → 재시작 → 코드에 wait/SIG_IGN, 컨테이너면 --init)입니다. 그리고 Z와 D를 혼동하지 마세요 — 하나는 죽은 기록, 하나는 산 채로 붙들린 겁니다.
