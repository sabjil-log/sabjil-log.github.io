> **한 줄 요약:** 배스천은 **관리자 SSH가 드나드는 유일한 문**입니다. 모든 서버의 22번을 인터넷에 여는 대신, 공개된 문 하나(배스천)만 지키고 나머지는 private에 숨기는 것 — 지킬 곳이 N개에서 1개로 줄어드는 게 핵심입니다.

## 문제: 문이 너무 많다

서버가 10대면 SSH 문이 10개. 공인 IP가 붙은 서버의 22번 포트에는 **몇 분 안에** 전 세계 봇들의 로그인 시도가 쏟아지기 시작합니다. `journalctl -u ssh | grep Failed`를 열어보면 장관이죠. 문이 10개면 자물쇠 관리(키 배포·회수, 패치, 로그 감시)도 10벌 — 하나만 삐끗해도 뚫립니다.

발상은 건물 설계와 같습니다. **모든 사무실에 외부 현관을 내지 말고, 경비가 지키는 정문 하나로 동선을 모으는 것.**

## 구조

```
관리자 → (인터넷) → [배스천: public 서브넷, 22만 허용] → [서버들: private, 배스천에서만 22 허용]
```

- **배스천**: public 서브넷의 작은 인스턴스. 하는 일이 "통과"뿐이라 뭘 깔지 않습니다 — 깔린 게 없어야 뚫을 것도 없으니까.
- **서버들**: private 서브넷. ACG를 **"배스천 ACG로부터의 22만 허용"**으로 — IP가 아니라 역할로 여는 그 체이닝(ACG 글) 그대로입니다.
- **배스천의 22**: 가능하면 전 세계가 아니라 **회사·VPN 대역만**. 문 하나로 모았으면 그 문도 좁혀야죠.

## ProxyJump — 두 번 접속을 한 번처럼

배스천에 들어가서 다시 ssh 치는 건 2005년 방식입니다. `-J`(ProxyJump) 하나면 **배스천을 경유하되 내 터미널에서 목적지로 직행**하는 것처럼 씁니다.

```bash
ssh -J bastion.example.com 10.0.3.15        # 배스천 경유 원샷
scp -J bastion.example.com app.tar 10.0.3.15:/tmp/   # 파일 전송도 그대로
```

`~/.ssh/config`에 박아두면 평생 씁니다.

```
Host bastion
    HostName bastion.example.com
    User taewan

Host 10.0.*
    ProxyJump bastion       # 이 대역은 전부 배스천 경유
    User taewan
```

이후로는 그냥 `ssh 10.0.3.15`. 중요한 보안 포인트 — ProxyJump는 **종단간 암호화가 유지**됩니다. 배스천은 터널을 이어줄 뿐 내 트래픽을 복호화하지 못해요. 그리고 **개인키를 배스천에 복사해두면 안 됩니다** — ProxyJump(또는 agent forwarding)를 쓰면 키는 내 노트북에만 있으면 됩니다. 배스천에 뒹구는 개인키는 그 자체가 사고입니다.

## 흔한 설계 실수 넷

**① 배스천에 이것저것 설치** — 모니터링 도구, 배포 스크립트, cron... 어느새 배스천이 중요 서버가 됩니다. 배스천은 **언제든 부수고 다시 만들 수 있는 빈 껍데기**여야 해요. 필요한 건 sshd와 로그뿐.

**② 만들어놓고 서버들 공인 IP를 안 뗌** — 정문을 세웠는데 옆문들이 열려 있으면 의미가 없습니다. 배스천 도입 = 다른 서버의 22 인바운드 전부 차단 + 공인 IP 회수까지가 한 세트.

**③ 계정 공유** — 다 같이 `ec2-user`로 들어가면 로그에 "누가"가 없습니다. 사람별 계정·키, 그리고 퇴사 시 즉시 회수(IAM 글의 오프보딩 그대로).

**④ 배스천 자체가 SPOF/장애 반경 무시** — 배스천이 죽으면 전 서버 접속 불가. 이미지를 떠두고 재생성 절차를 문서화하거나, 중요 환경이면 존 분산(리전·AZ 글의 그 원칙)까지.

## 요즘 흐름: 문 자체를 없애기

클라우드 벤더들은 한 발 더 나가서 **SSH 포트를 아예 안 여는** 접속 방식을 제공합니다 — AWS SSM Session Manager가 대표적이고, NCP도 콘솔 기반 서버 접속 기능이 있죠. 에이전트가 아웃바운드로 접속을 맺기 때문에 인바운드 22가 **0개**가 되고, 접속 기록·세션 로그가 IAM과 통합됩니다. 신규 설계라면 이쪽을 1순위로 검토하고, 배스천은 그게 안 되는 환경(규제, 하이브리드)의 표준 대안으로 보는 게 현재 감각입니다.

## 한 줄 정리

배스천의 본질은 **지킬 문을 1개로 줄이는 것**입니다. private + ACG 체이닝 + ProxyJump(키는 노트북에만)가 기본형, 배스천은 빈 껍데기로 유지, 옆문(각 서버 공인 22)은 반드시 폐쇄 — 그리고 가능하다면 문 자체가 없는 SSM류가 다음 단계입니다.
