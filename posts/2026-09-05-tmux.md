> **한 줄 요약:** SSH 세션이 끊기면 그 위에서 돌던 프로세스도 함께 죽습니다(HUP 신호). tmux는 **서버 안에 독립된 작업실을 만들고 거기 들어가서 일하는 것** — 연결이 끊겨도 작업실은 남아 있고, 다시 붙으면 화면까지 그대로입니다. 명령 다섯 개면 실무가 됩니다.

[[diagram:tmux-session]]

## 왜 필요한가

- rsync로 500GB 이관 중 노트북이 절전에 들어감 → 처음부터(그 글의 재개가 있어 다행이지만 시간은 날아감)
- 배포 스크립트 실행 중 사무실 와이파이가 끊김 → 절반만 배포된 상태
- 장애 대응 중 터미널을 닫아야 하는데 tail -f 로그를 놓치고 싶지 않음

`nohup`이나 `&`로도 프로세스는 살릴 수 있지만, **화면(출력·진행률·대화형 입력)은 잃습니다.** tmux는 화면째로 보존합니다.

## 개념: 서버 안의 작업실

```
[내 노트북] --ssh--> [서버]
                      └─ tmux 세션 "deploy"  ← 작업실 (SSH와 독립)
                            ├─ 창(window) 0: 배포 스크립트
                            └─ 창 1: 로그 tail
```

내가 접속을 끊어도(detach) 작업실은 그대로 돌아갑니다. 다시 접속해 attach하면 **떠날 때 화면 그대로** 이어집니다. 배스천을 거쳐 들어가는 환경이라면 특히 체감이 큽니다 — 중간 어느 홉이 끊겨도 작업은 무사하니까요.

## 명령 다섯 개

```bash
tmux new -s deploy        # ① 'deploy'라는 작업실 만들고 들어가기
# (작업 실행...)
# ② 나오기: Ctrl+b 누르고 손 뗀 뒤 d   (detach)
tmux ls                   # ③ 작업실 목록 — 뭐가 살아있나
tmux attach -t deploy     # ④ 다시 들어가기
exit                      # ⑤ 작업 끝났으면 작업실 정리
```

핵심은 **Ctrl+b**가 "지금부터 tmux에게 말한다"는 신호라는 것. 그다음 한 글자가 명령입니다.

```
Ctrl+b d      나오기 (detach)
Ctrl+b c      새 창 만들기
Ctrl+b 0/1/2  창 번호로 이동
Ctrl+b "      화면을 위아래로 쪼개기 (pane)
Ctrl+b %      좌우로 쪼개기
Ctrl+b 방향키  쪼갠 화면 간 이동
Ctrl+b [      스크롤 모드 (q로 나옴) ← 위쪽 출력 보기
```

처음엔 `d / c / 숫자 / "` 네 개만 써도 충분합니다. 나머지는 필요할 때 찾으면 되고요.

## 실무 패턴 셋

**① 장시간 작업은 무조건 tmux 안에서.**
```bash
tmux new -s migrate
rsync -avP --delete /data/ new-server:/data/
# Ctrl+b d 로 나오고, 퇴근. 다음날 tmux attach -t migrate 로 확인
```

**② 장애 대응용 다창 배치.** 창 0에 명령, 창 1에 `journalctl -f`, 창 2에 `watch -n2 'ss -s'`. Ctrl+b 숫자로 오가며 보는 게 터미널 여러 개 띄우는 것보다 안정적입니다 — 연결이 끊겨도 배치가 유지되니까요.

**③ 이미 시작한 작업이 tmux 밖이라면.** 늦었습니다 — 그래서 습관이 중요해요. 서버에 붙으면 **무조건 tmux 먼저**. 그리고 `.bashrc`에 붙이는 자동 attach는 편하지만 스크립트·자동화 세션까지 잡아채 사고를 만드니, 수동으로 치는 걸 권합니다.

## 알아두면 좋은 것

- **세션 이름은 목적으로.** `tmux new -s migrate-goil` 처럼. 나중에 `tmux ls`에서 "이게 뭐였지"가 없어야 합니다.
- **서버 재부팅에는 안 살아남습니다.** tmux는 그 서버의 프로세스니까요. 재부팅을 넘겨야 하는 작업은 systemd 서비스로(fd 글의 그 세계) 만드는 게 맞습니다.
- **screen과의 관계.** 오래된 서버엔 `screen`만 있을 수 있습니다. 개념은 같고 키만 다릅니다(Ctrl+a). 둘 중 있는 걸 쓰면 되고, 새로 배운다면 tmux.
- **긴 출력은 파일로도.** tmux 스크롤 버퍼는 유한합니다. 중요한 작업은 `| tee /tmp/작업.log`로 남기세요 — 나중에 grep할 수 있는 형태로.

## 한 줄 정리

**서버에 붙으면 tmux 먼저.** `new -s 이름` → 작업 → `Ctrl+b d` → `attach -t 이름`, 이 넷이 8할입니다. 연결이 끊겨도 화면째로 살아남고, 장애 대응 때는 창을 나눠 쓰세요 — 다만 재부팅을 넘길 작업은 tmux가 아니라 systemd의 일입니다.
