> **한 줄 요약:** MTU는 한 번에 보낼 수 있는 **패킷의 최대 크기**입니다. VPN·터널은 자기 헤더를 덧붙여 봉투를 작게 만드는데, 큰 패킷이 여기 걸리면 쪼개지거나(조각화) **DF 플래그가 붙어 있으면 통째로 버려집니다.** "일부만 안 되는" 증상의 단골 원인이에요.

[[diagram:mtu-fragmentation]]

## 증상이 유별나다

이 문제의 특징은 **"반쯤 되는"** 것입니다.

- `ping`은 정상 (작은 패킷이니까)
- SSH 접속은 되는데 `ls -la` 출력이 긴 순간 멈춤
- 로그인 페이지는 열리는데 이미지 많은 페이지에서 무한 로딩
- 어떤 사이트는 되고 어떤 사이트는 안 됨

방화벽 문제라면 아예 안 될 텐데 **크기에 따라** 갈리죠. 그게 MTU의 지문입니다.

## 원리: 봉투 크기와 덧붙는 헤더

이더넷의 표준 MTU는 **1500바이트**입니다. 우체국이 받아주는 봉투 최대 크기라고 보면 돼요. 그런데 VPN·터널을 지나면 원래 패킷을 **새 봉투에 넣어 다시 포장**합니다(캡슐화). 겉봉투는 여전히 1500이니, 안에 들어갈 내용은 그만큼 줄어들죠.

```
일반 경로:   [ 데이터 1460 ][ TCP/IP 헤더 40 ]              = 1500 ✓
VPN 경로:    [ 데이터 1460 ][ TCP/IP 40 ][ 터널 헤더 60 ]  = 1560 ✗ 초과!
```

그래서 터널 구간의 실효 MTU는 1400 근처로 떨어집니다. 이 사실을 모르는 양쪽 끝은 계속 1500짜리를 보내고요.

## 초과했을 때 벌어지는 두 갈래

**① 조각화(fragmentation)** — 라우터가 큰 패킷을 두 개로 쪼개 보냅니다. 느려지지만 통신은 됩니다.

**② 폐기 + ICMP 회신** — 요즘 TCP 패킷에는 대개 **DF(Don't Fragment) 플래그**가 붙어 있습니다. "쪼개지 말라"는 뜻이죠. 이때 라우터는 패킷을 버리고 **"너무 커, 1400으로 줄여"라는 ICMP 메시지**를 보냅니다. 발신자가 이걸 받으면 크기를 낮춰 재전송해요 — 이 자동 협상이 **PMTUD(Path MTU Discovery)**입니다.

## 진짜 범인: 막힌 ICMP

정상이라면 ②의 협상으로 스스로 해결됩니다. 문제는 많은 방화벽이 **"ICMP는 보안상 다 막자"**로 설정돼 있다는 것. 그러면 —

```
발신자: 1500 보냄 → 라우터가 버림 → ICMP 회신 → 방화벽이 ICMP 차단 → 발신자는 아무것도 못 들음
발신자: (응답이 없네) 1500 재전송 → 또 버려짐 → 또 침묵 → 무한 반복
```

이것이 **PMTUD 블랙홀**입니다. 연결은 맺어졌는데(작은 패킷이라) 큰 데이터에서 영구 정지하는 그 기묘한 증상의 정체예요.

## 확인하는 법

DF 플래그를 켠 채 크기를 바꿔가며 핑을 던져 경계를 찾습니다.

```bash
# Linux — -M do 가 DF 설정, -s 는 페이로드 크기(헤더 28 제외)
ping -M do -s 1472 example.com     # 1472+28 = 1500 — 성공하면 MTU 1500 OK
ping -M do -s 1372 example.com     # 1400 상당 — 이건 되고 위는 안 되면 MTU가 1400대

# macOS
ping -D -s 1472 example.com
# Windows
ping -f -l 1472 example.com
```

`Frag needed and DF set` 또는 "패킷을 조각화해야 합니다"가 뜨면 그 크기가 경로 MTU를 넘은 겁니다. 성공하는 최대 `-s` 값 + 28이 실제 경로 MTU예요.

현재 인터페이스 설정과 실제 오가는 크기도 봅니다.

```bash
ip link show | grep -E "mtu"          # 인터페이스별 MTU (tun0/wg0 등 터널 확인)
sudo tcpdump -ni any 'icmp[icmptype] == 3'   # ICMP unreachable(조각화 필요) 수신 여부
```

## 처방 — 위에서 아래로

**① ICMP type 3 code 4를 허용하라.** 근본 처방입니다. 방화벽에서 ICMP를 전부 막지 말고 "조각화 필요" 메시지만은 통과시키세요. 이러면 PMTUD가 제 일을 합니다.

**② 터널 인터페이스 MTU를 낮춘다.**

```bash
sudo ip link set dev wg0 mtu 1380     # WireGuard 등 터널 장치
```

**③ MSS 클램핑** — 서버·라우터에서 TCP 협상 단계의 최대 세그먼트 크기를 경로에 맞게 깎아버리는 방식입니다. 양 끝단을 못 건드릴 때(고객사 네트워크 등) 게이트웨이에서 쓰는 실전 카드예요. VPN 게이트웨이·로드밸런서에 이 옵션이 있는지 확인하세요.

**④ 클라우드라면 점보 프레임 확인.** 일부 환경은 내부 통신에 9001 등 큰 MTU를 쓰는데, 그 트래픽이 1500 구간(인터넷, 일부 게이트웨이)으로 나가면 같은 문제가 생깁니다. 인스턴스 MTU와 경로를 대조해보세요.

## 한 줄 정리

**"작은 건 되고 큰 건 안 된다"** = MTU를 의심하세요. `ping -M do -s`로 경계를 찾고, 근본 처방은 **ICMP(조각화 필요) 허용**, 차선은 터널 MTU 하향이나 MSS 클램핑입니다. 보안이라며 ICMP를 통째로 막는 게 이 사고의 절반을 만듭니다.
