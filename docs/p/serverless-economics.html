❯ 서버리스는 언제 싸고 언제 비싼가 — 택시 요금의 경제학

한 줄 요약: 서버리스(FaaS)는 택시입니다 — 탄 만큼만 내니 가끔 탈 땐 압도적으로 싸고, 매일 종일 타면 차 사는 것(상시 서버)보다 비쌉니다. 기준은 하나예요: 트래픽이 간헐적인가, 상시적인가. 그리고 요금표 밖의 비용(콜드스타트, 실행시간 상한, 주변 요금)까지 봐야 진짜 계산이 됩니다.

요금 구조부터 — 뭘 안 내고 뭘 내나

상시 서버는 시간당 냅니다 — 트래픽이 0이어도, 새벽에도(비용 누수 글의 그 밤샘 서버). 서버리스는 호출 수 × 실행시간 × 메모리로 냅니다 — 안 부르면 0원.

이 차이가 만드는 두 극단:

  • 월 10만 호출, 평균 200ms짜리 웹훅 처리기 — 서버리스면 사실상 무료 구간, 상시 서버면 최소 인스턴스 한 달치. 수십 배 차이로 서버리스 승.
  • 초당 수백 요청이 24시간 — 같은 일을 하는 상시 서버 몇 대 값을, 서버리스는 호출 단가로 곱해 받습니다. 트래픽이 고르게 꽉 차 있을수록 서버 쪽이 수 배 저렴해져요. 택시로 출퇴근을 넘어 상주시키는 격이니까요.

손익분기는 요금표에 따라 움직이지만 감각은 이렇습니다 — 평균 가동률이 한 자릿수 %면 서버리스, 수십 %를 상시 유지하면 서버(또는 컨테이너), 그 사이는 계산기. 그리고 트래픽이 뾰족뾰족(스파이크)하면 서버리스의 자동 확장이 오토스케일링 글의 그 느린 확장·사각지대 고민을 통째로 없애준다는 가점이 붙습니다.

요금표 밖의 비용 셋

① 콜드스타트. 한동안 안 불린 함수는 첫 호출 때 실행 환경을 새로 깨우느라 수백 ms~수 초가 붙습니다. TTFT에 민감한 사용자 대면 API라면 p95가 이걸로 오염돼요(알람 글의 그 p95). 완화책 — 가벼운 런타임·작은 패키지(멀티스테이지 다이어트의 함수 버전), 워밍/프로비저닝드 동시성(단, 이건 상시 과금이라 서버리스의 존재 이유를 갉아먹는 절충입니다), 또는 지연 민감 경로만 상시 서버로 분리.

② 실행 모델의 상한. 최대 실행시간(수 분~15분급), 메모리 상한, 그리고 매 호출이 무상태라는 전제. 긴 배치·대용량 처리·상시 연결(웹소켓)은 구조적으로 안 맞습니다. "함수에서 DB 커넥션 풀이 이상해요"가 전형적 충돌 — 인스턴스가 수백 개로 불어나면 커넥션도 수백 개라, DB 쪽 max_connections(관리형 DB 글의 그 파라미터)를 때립니다. 프록시(RDS Proxy류)나 HTTP 기반 데이터 접근이 처방이고요.

③ 주변 요금. 함수 자체는 싼데 문 앞이 비쌉니다 — API Gateway 호출당 요금, NAT을 지나는 아웃바운드(그 글의 GB당), 로그 수집(중앙화 글의 그 비용), 호출 간 큐/이벤트 서비스. "함수 요금 3만 원, 게이트웨이 30만 원" 청구서가 실제로 나옵니다. 견적은 함수가 아니라 파이프라인 전체로 내세요.

그럼 어디에 쓰나 — 어울리는 일의 목록

  • 이벤트 반응형 접착제: 버킷에 파일 오면 썸네일, 웹훅 받으면 처리, 알람 오면 슬랙 — cron 글의 그 잡무들이 서버 없이 굴러갑니다 (스케줄 실행도 되니 "크론 돌릴 서버" 자체가 사라짐)
  • 간헐·예측불가 트래픽 API: 사내 도구, 월말에만 몰리는 정산, 이벤트성 페이지
  • 트래픽 0의 시간이 긴 것 전부: 개발·스테이징 환경의 API (밤샘 서버 문제의 구조적 해결)

반대로 — 상시 고트래픽 코어 API, 장시간 배치, 상태·연결 유지가 필요한 것은 서버/컨테이너의 일입니다. 실전은 혼합이에요: 코어는 서버로, 가장자리(이벤트·글루·간헐)는 서버리스로. "전부 서버리스" 선언은 "전부 마이크로서비스"와 같은 냄새가 납니다 — 멀티에이전트 글의 그 기준을 여기에도: 쪼개서(옮겨서) 얻는 게 명확할 때만.

잊지 말 것 — 운영이 사라지진 않는다

"서버리스 = 노운영"은 절반만 참입니다. 패치·용량은 사라지지만 관측은 오히려 어려워져요 — 인스턴스에 들어가 볼 수(exec) 없고, 로그·트레이싱이 유일한 눈입니다(중앙화 글의 trace_id가 여기선 선택이 아니라 생존). 그리고 함수가 수십 개로 늘면 "이 함수 누구 거야?"가 서버보다 심하게 옵니다 — 태그 세 장(owner/project/expire)은 함수에도 똑같이.

한 줄 정리

서버리스의 손익은 가동률이 정합니다 — 간헐이면 택시(압승), 상시면 자가용(서버) 역전. 콜드스타트·실행 상한·주변 요금까지 파이프라인 전체로 견적 내고, 코어는 서버·가장자리는 서버리스로 섞는 것 — 그리고 관측(trace_id)과 태그는 함수라고 면제되지 않습니다.
