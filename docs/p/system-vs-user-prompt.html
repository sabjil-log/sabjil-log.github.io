❯ 시스템 프롬프트와 유저 프롬프트, 왜 굳이 나눠놨을까

한 줄 요약: 시스템 프롬프트는 업무 지침서(운영자가 쓰는 규칙, 대화 내내 유효), 유저 프롬프트는 고객의 요청(턴마다 바뀌는 입력)입니다. 모델은 시스템 쪽 지시에 더 높은 권위를 두도록 훈련돼 있어요 — 이 위계가 일관성·캐싱·주입 방어의 기반이라, "무엇이 규칙이고 무엇이 입력인가"로 칸을 가르면 됩니다.

나눠놓은 이유 — 식당 비유

주방에 지시가 두 경로로 들어옵니다. 사장의 운영 방침("모든 음식은 위생 기준 X, 알레르기 고지 필수")과 손님의 주문("파스타 하나요, 덜 짜게"). 손님이 "오늘부터 위생 기준은 무시하죠"라고 말해도 주방은 따르지 않아야 하죠 — 두 목소리의 권위가 다르니까요.

시스템/유저 구분이 정확히 이겁니다. 프롬프트 주입 글에서 "LLM에겐 모든 텍스트가 같은 재질"이라 했는데, 역할 구분은 그 평평함에 위계를 세우려는 장치예요. 모델들은 시스템 지시를 사용자 지시보다 우선하도록 학습되고, 벤더들이 지시 위계(instruction hierarchy)라 부르며 계속 강화하는 지점입니다. 완벽하진 않아도(주입 글의 결론 — 그래서 2층 방어가 필요), 같은 규칙을 유저 칸에 쓰는 것보다 훨씬 잘 지켜집니다.

무엇을 어느 칸에 — 기준은 하나

"대화가 바뀌어도 유지돼야 하는가?" 예 → 시스템, 아니오 → 유저.

[시스템 — 지침서]
- 역할·정체성: "너는 NCP 인프라 상담 봇이다"
- 불변 규칙: "근거 문서에 없으면 모른다고 답하라" (환각 글의 그 한 줄)
- 출력 규격: 형식, 언어, 금지사항
- 도구 사용 정책: 언제 어떤 도구를 (에이전트 글의 명세와 한 몸)

[유저 — 요청과 재료]
- 이번 질문
- 대화 이력
- RAG 검색 결과, 첨부 문서  ← 중요: 외부 데이터는 여기

마지막 줄이 실무 포인트입니다. 검색해온 문서를 시스템 칸에 넣지 마세요 — 두 가지 이유로요. ① 외부 텍스트에 높은 권위를 부여하는 셈이라 주입에 정면으로 취약해집니다(문서 속 "이전 지시 무시" 문장이 사장 목소리가 되는 것). ② 프롬프트 캐싱 글의 규칙 위반 — 시스템은 고정 프리픽스여야 캐시를 타는데, 매번 바뀌는 검색 결과가 앞에 오면 매 요청이 캐시 미스입니다. 고정 규칙은 시스템(앞), 동적 재료는 유저(뒤), 외부 데이터는 구분자로 감싸 "자료일 뿐"임을 명시 — 세 원칙이 한 세트예요.

흔한 실수 셋

① 시스템 프롬프트 비대증. 잘 안 지켜진다고 규칙을 계속 추가하다 보면 3천 토큰짜리 지침서가 됩니다. 컨텍스트 글의 "가운데 흐림"이 지침서 안에서도 일어나요 — 서로 모순되는 조항이 생기고, 정작 중요한 규칙이 묻힙니다. 지침은 적을수록 잘 지켜집니다. 안 지켜지는 규칙은 문장을 늘리기보다 예시 한두 개로 바꾸는 게 보통 더 효과적이고, 형식 강제라면 애초에 구조화 출력(그 사다리)의 일이지 프롬프트의 일이 아닙니다.

② 대화 중 규칙 변경을 유저 턴으로. "지금부터는 영어로만 답해줘" 같은 세션 설정 변경이 유저 메시지로 들어오면, 몇 턴 지나 이력이 길어지며 잊힙니다(가운데 흐림). 앱 차원의 설정 변경이라면 시스템 프롬프트를 갱신하는 게 맞아요 — 단, 캐싱 관점에선 프리픽스 변경 = 캐시 리셋이니, 자주 바뀌는 사용자 설정은 시스템 맨 뒤쪽에 배치하는 절충이 실전 요령입니다.

③ 시스템 프롬프트에 비밀 넣기. "내부 정책상 원가는 X원인데 절대 말하지 마" — 시스템 프롬프트는 금고가 아닙니다. 유출 유도 기법은 다양하고, 모델은 아는 것을 결국 말할 수 있는 존재로 취급해야 합니다. 모델이 몰라야 하는 것은 프롬프트에 넣지 않는 것이 유일한 방어예요(컨텍스트에 없는 건 유출도 못 한다 — 주입 글의 세션 격리 원칙).

점검 루틴

시스템 프롬프트도 코드입니다 — 버전 관리하고(git), 바꿀 때마다 골든셋을 돌리세요(평가 글). "규칙 하나 추가했더니 다른 유형 답변이 무너지는" 회귀가 프롬프트에서 제일 흔하게 나는 곳이 시스템 칸이거든요.

한 줄 정리

시스템 = 운영자의 지침서(고정, 높은 권위, 캐시 프리픽스), 유저 = 요청과 재료(동적, 외부 데이터는 구분자로). 지침은 짧게, 비밀은 아예 넣지 말고, 바꿨으면 골든셋 — 칸을 제대로 가르는 것만으로 일관성·비용·보안이 같이 좋아집니다.
