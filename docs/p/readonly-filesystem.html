❯ 디스크가 갑자기 읽기전용이 됐다 — 파일시스템의 자기방어

한 줄 요약: 파일시스템이 읽기전용으로 바뀌는 건 고장이 아니라 커널의 자기방어입니다. 손상을 감지했을 때 "더 쓰면 더 망가진다"며 스스로 잠그는 것 — 그래서 재부팅으로 풀기 전에 dmesg에서 왜 잠갔는지를 읽어야 합니다.

증상

$ touch /var/log/test
touch: cannot touch '/var/log/test': Read-only file system
$ df -h        # 용량은 멀쩡 (inode 글의 그 함정도 아님)

앱은 로그를 못 써서 조용히 실패하고, DB는 쓰기 에러를 뿜고, 세션 파일을 못 만들어 로그인이 안 됩니다. 그런데 읽기는 다 되니 "디스크가 죽은 건 아닌데?" 싶죠.

왜 잠그나 — 출혈을 멈추는 지혈대

EXT4 같은 파일시스템에는 errors=remount-ro라는 기본 마운트 옵션이 있습니다. 에러를 만나면 읽기전용으로 재마운트하라는 뜻이에요. 이유는 명확합니다 — 메타데이터가 이미 깨진 상태에서 계속 쓰면 손상이 번지고 복구 가능성이 낮아집니다. 환자가 피를 흘릴 때 달리기를 멈추게 하는 것과 같아요.

즉 읽기전용 상태는 결과이고 증상입니다. 원인은 그전에 일어났고, 그 기록은 커널 로그에 있습니다.

원인 찾기 — dmesg가 사건 기록부

sudo dmesg -T | grep -iE "error|remount|I/O|ext4|nvme|sd[a-z]" | tail -30

패턴별 해석:

① 물리 디스크 오류

blk_update_request: I/O error, dev sda, sector 12345678

디스크나 케이블, 클라우드라면 스토리지 계층의 문제입니다. SMART로 확인하고(smartctl -a /dev/sda), 클라우드면 콘솔의 볼륨 상태·이벤트를 봅니다. 이 경우는 볼륨 교체 + 스냅샷 복구(그 글의 시나리오)가 답입니다.

② 파일시스템 메타데이터 손상

EXT4-fs error (device sda1): ext4_lookup: deleted inode referenced

갑작스러운 전원 차단, 이전의 비정상 종료가 남긴 상처. fsck가 처방입니다.

③ 네트워크 스토리지 단절 — NFS/EFS 마운트가 끊기면 같은 증상이 납니다. strace 글에서 본 그 "read에서 멈춘" 상태와 사촌이죠. 네트워크·마운트 옵션을 봅니다.

④ 클라우드 특수 케이스 — 볼륨 자체가 읽기전용으로 붙거나, 스냅샷에서 복원한 볼륨이 라벨 충돌을 일으키는 경우. lsblk -o NAME,RO,MOUNTPOINT에서 RO 컬럼이 1이면 블록 장치 레벨입니다.

복구 순서

# 0) 현재 마운트 상태 확인 — 정말 ro 인가
mount | grep " / \| /var "        # (ro, ...) 표시 확인

# 1) 원인이 ②(메타데이터)이고 데이터 디스크라면: 언마운트 후 검사
sudo umount /data
sudo fsck -y /dev/sdb1            # -y 는 자동 수정 — 로그를 꼭 남기세요
sudo mount /data

# 2) 루트(/)가 잠긴 경우: 재부팅이 필요 (부팅 중 자동 fsck)
#    급하면 임시 rw 재마운트로 응급조치 — 원인 모른 채 쓰면 위험
sudo mount -o remount,rw /

중요한 순서 감각: remount,rw는 지혈대를 풀어버리는 것입니다. 원인이 ①(물리 오류)인데 이걸 하면 손상을 키웁니다. dmesg를 먼저 읽고, 물리 오류가 아닌 게 확인됐을 때만 응급 재마운트를 쓰세요. 그리고 재부팅은 증상을 지우는 대신 dmesg 기록도 지웁니다 — journalctl -k -b -1로 이전 부팅의 커널 로그를 볼 수 있다는 걸 기억해두면 사후 수사가 가능합니다.

예방 감각

  • 디스크 사용률 알람(알람 설계 글의 그 시한폭탄 예외 항목) — 꽉 찬 디스크가 손상의 방아쇠가 되는 경우가 있습니다
  • 정기 재부팅 시 fsck 통과 확인 — 오래 안 껐다 켠 서버는 상처를 안고 달리는 중일 수 있어요
  • 상태는 디스크 밖으로 — 로그는 중앙화, 데이터는 볼륨 분리. 루트 디스크가 잠겨도 서비스가 죽지 않게 (소모품 서버 철학의 실익)

한 줄 정리

읽기전용 전환은 커널이 켠 지혈대입니다. 재부팅으로 풀기 전에 dmesg로 물리 오류인지 메타데이터 손상인지 가르고 — 전자면 볼륨 교체+스냅샷 복구, 후자면 fsck. 원인 모르고 remount,rw 하는 게 이 사고를 진짜 재앙으로 만드는 유일한 방법입니다.
