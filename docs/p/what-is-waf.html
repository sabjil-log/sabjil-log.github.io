❯ 방화벽이 있는데 왜 WAF가 또 필요하죠 — 겉봉투 검사와 내용물 검사

한 줄 요약: 네트워크 방화벽(ACG·NACL)은 겉봉투(IP·포트) 검사라, 정식으로 열어둔 443으로 들어오는 내용물 공격(SQL 인젝션, XSS)은 통과시킵니다. 그 층을 맡는 게 WAF — HTTP 요청의 내용을 읽고 공격 패턴을 거르는 L7 검문소입니다. 위치도 딱 그래서, ALB처럼 "뜯어 읽는" 계층에 붙어요.

방화벽이 못 보는 것

ACG 글의 그 경비를 다시 소환하면 — 방 앞 경비(ACG)는 "어디서 온 누가, 몇 번 문으로"만 봅니다. 웹서비스라면 "전 세계 → 443 허용"이 정상 설정이고, 경비는 그 규칙대로 성실하게 통과시키죠. 문제는 공격자도 정문으로, 정장을 입고 들어온다는 것.

GET /products?id=1              ← 정상 손님
GET /products?id=1' OR '1'='1   ← 같은 문, 같은 포트 — 내용물만 흉기

겉봉투 기준으로 두 요청은 완전히 동일합니다. 이 차이는 편지를 뜯어 읽어야만 보여요 — ALB vs NLB 글의 그 구분이 보안에서 반복되는 겁니다. L3/4 방화벽은 구조적으로 이 층을 못 봅니다. 못 하는 게 아니라 역할이 아닌 거죠.

WAF가 거르는 것들

WAF는 HTTP 요청의 URL·파라미터·헤더·바디를 읽고 패턴을 검사합니다. 대표 표적 —

  • SQL 인젝션 — 파라미터에 쿼리 조각(' OR 1=1, UNION SELECT)을 심어 DB를 조작. 프롬프트 주입 글에서 "SQL 인젝션엔 완치법이 있다"고 했던 바로 그 공격의 현장입니다. (완치는 코드의 파라미터 바인딩이고, WAF는 그 앞의 검문 — 뒤에서 다시.)
  • XSS — 입력에 <script>를 심어 다른 사용자 브라우저에서 실행시키기.
  • 경로 조작·파일 포함 — ../../etc/passwd 류.
  • 알려진 취약점 시그니처 — 특정 프레임워크 CVE를 노리는 정형화된 요청. 패치 배포 전까지 WAF 규칙으로 급한 불을 끄는 가상 패치가 실무에서 꽤 요긴합니다.
  • 비정상 트래픽 행태 — 한 IP의 과도한 요청(레이트리밋), 봇 시그니처, 크리덴셜 스터핑 패턴.

관리형 WAF(NCP Web Security Checker/WAF 계열, AWS WAF)는 이런 것들이 관리형 규칙 세트로 제공돼서, 켜는 것 자체는 어렵지 않습니다. 어려운 건 운영이에요 — 다음 얘기.

실전의 진짜 문제: 오탐

WAF 도입 후 단골 사고 — 정상 요청이 차단됩니다. 게시판에 SQL 강의 글을 쓰는 사용자(본문에 SELECT * FROM이…), JSON 바디에 HTML을 담는 에디터, 특수문자가 많은 검색어. 규칙 입장에선 전부 공격처럼 생겼거든요.

그래서 정석 도입 순서는 알람 설계 글의 감각과 같습니다.

1. 감지 모드(Count/Detection)로 시작 — 차단하지 않고 기록만
2. 몇 주간 로그 검토 — 뭐가 걸리는지, 오탐이 어디서 나는지
3. 오탐 경로는 예외 규칙(특정 경로·파라미터 제외)으로 다듬고
4. 차단 모드 전환 — 그것도 위험도 높은 규칙군부터 단계적으로

첫날부터 전체 차단 모드는 "보안 켰더니 서비스가 죽었다"의 지름길입니다. 그리고 차단 로그는 반드시 중앙 로그로 — 어떤 규칙이 뭘 막았는지가 남아야 오탐 수사가 됩니다(로그 중앙화 글의 그 이유).

WAF는 어디에 서나

내용을 읽어야 하니 암호화가 풀리는 지점 뒤에 서야 합니다 — 즉 TLS를 종료하는 ALB/CDN 층. 그래서 클라우드 WAF들이 ALB·CloudFront·API Gateway에 "부착"하는 형태인 거예요. NLB(안 뜯는 계층)에는 붙일 수 없는 이유이기도 하고요.

방어선 전체를 겹쳐 보면:

[네트워크 방화벽] 겉봉투 — 포트·IP·대역        (ACG·NACL)
[WAF]           내용물 — HTTP 패턴·행태        (ALB/CDN 층)
[애플리케이션]    근본 — 파라미터 바인딩·이스케이프·검증

중요한 순서 감각: WAF는 코드 수정을 대체하지 않습니다. 인젝션의 완치는 여전히 파라미터 바인딩(코드)이고, WAF는 ① 패치 전 가상 패치, ② 알려진 패턴의 대량 소음 제거, ③ 심층 방어의 한 겹입니다. "WAF 있으니 코드는 대충"이 되는 순간, 우회 기법 하나에 전 층이 뚫려요 — 프롬프트 주입 글의 "1층은 완화, 2층이 본선" 구조가 여기서도 그대로입니다.

한 줄 정리

방화벽은 겉봉투, WAF는 내용물 — 정상 포트로 들어오는 인젝션·XSS는 WAF의 영역입니다. TLS가 풀리는 층(ALB/CDN)에 붙이고, 감지 모드→오탐 다듬기→단계적 차단으로 들이며, 완치(코드의 바인딩·검증)를 대체하는 게 아니라 그 앞의 검문이라는 위치 감각까지 — 이게 WAF의 전부입니다.
